# 食物图片识别：隐私、评测与回退规格

> Status: Proposed
> Date: 2026-07-28
> Scope: 阶段 9 仅“食物图片识别、份量估算和用户校正”单项。本文件不是平行路线图。

## 产品边界

目标流程是：用户主动拍照或选择一张食物照片 → 本地预览 → 明示上传 → 生成低/中置信度
候选 → 用户修改名称、餐别、份量和热量 → 用户确认后写入。任何模型结果都不能绕过确认。

本单项不包含身体照片、体脂估算、人脸/年龄/身份识别、视频动作纠正、语音、手机号、健康
平台或通知。Journey 只提供一般营养记录辅助，不把图片估算当作医学、诊断或精确测量结果。

## Provider 决策门禁

| Provider | 图片能力 | 当前状态 | 启用条件 |
|---|---|---|---|
| Mock | 不识别真实图片，只返回明确标记的演示候选 | 本轮默认、CI 可用 | 零 Key、零外部调用 |
| DeepSeek V4 | 官方明确为 text-only | 禁止用于图片 | 不适用；仍可负责文字 Agent |
| Qwen `qwen3.7-flash` | 北京区域接口已实测图片输入和非思考结构化输出 | Proposed 首选；100 张真实评测已完成但未达全部门禁 | Top-3 与份量误差达标后重新评审 |
| OpenAI/OpenAI-compatible 视觉模型 | 取决于具体模型和端点 | 备选 | 同样逐模型评审，不共享错误凭据 |

本轮不得因为 `.env` 已有 DeepSeek Key 就发送图片。真实视觉 Provider 与文本 Provider 分开，
避免为了图片能力替换整个 Agent。

## 数据最小化和生命周期

1. 相机/相册权限只在按钮点击后请求；权限被拒时不反复弹窗。
2. 每次只处理一张图。客户端不请求 EXIF，压缩质量为 0.65，并提示裁剪无关人物和背景。
3. API 只接受声明尺寸不超过 4096×4096、解码后不超过 5 MiB 的 JPEG、PNG 或 WebP。
4. Journey 请求中的 base64 和图片字节只存在于客户端状态和 API 请求内存；不写 Journey
   磁盘、数据库、日志、Trace、RAG、备份或错误详情。用户明示上传后，供应商侧处理仍受其
   服务协议和法定留存要求约束，不能表述为“第三方绝不留存”。
5. Trace 只允许记录媒体类型、字节数、宽高、Provider、模型、Token、费用、延迟、是否降级。
6. 用户取消、请求完成或失败后立即释放图片引用。饮食记录只保存用户确认后的结构化字段，
   `source=image`，不保存图片或文件名。
7. 不接受或分析无关敏感图片；检测到非食物或无法判断时必须 abstain，转手动记录。

## 输出契约

候选必须包含：检测到的食物项、每项份量估计、建议餐别、总热量点估计、总热量最小/最大值、
置信度、假设列表、是否需要用户校正。以下约束不可放宽：

- `needs_user_correction` 恒为 `true`。
- `energy_min_kcal <= energy_kcal <= energy_max_kcal`。
- 对非食物、严重遮挡或无尺度参照图片返回 `manual_required`，不得编造精确食物名称。
- UI 同时展示宽区间和“估算”标签；写入表单中的点估计可修改。
- Mock 必须显示“演示候选，未真实识别图片”。

## 供应商政策复核

2026-07-28 复核当前有效的阿里云百炼服务协议与隐私声明：

- 服务协议要求服务商按用户指示处理输入，不得用于自身目的或未经授权披露；未获用户授权
  不得将用户内容用于模型训练，并要求在服务终止后的约定缓冲期后删除副本。
- 用户必须对上传图片拥有所有权、许可或其他合法授权，因此评测集逐条固定来源与许可。
- 隐私声明说明模型调用数据会在满足法律要求的范围内保存，并采用 AES-256 等保护措施；
  官方公开页面没有给出模型调用内容的精确保留天数。这一不确定性是当前 Proposed ADR 的
  残余风险，真实用户照片必须逐次明示同意，且不得上传无关人物或敏感内容。
- 北京区域 Base URL 只证明所选服务区域；不能据此推断数据从不跨区或零留存。若未来公网
  发布，必须重新核对届时合同、地域、删除请求渠道与隐私文案。

官方依据：[阿里云百炼服务协议](https://terms.alicdn.com/legal-agreement/terms/common_platform_service/20230728213935489/20230728213935489.html)、
[模型服务灵积隐私声明](https://help.aliyun.com/en/model-studio/privacy-notice)。

## 真实评测结果

三轮均使用同一 100 张锁定数据集、本机北京端点、独立 Qwen Key 和每日人民币 1 元预算；
报告不保存原图、base64 或 Key。v1.1 的长 Prompt 导致超时和结构化失败增加，因此回退为
精简 JSON Prompt；v1.2 增加双语规范名、有限的确定性 Schema 归一化和更宽但有界的热量区间。

| 指标 | Baseline v1.0 | v1.1 | v1.2 | 门槛 | v1.2 |
|---|---:|---:|---:|---:|---|
| Schema 有效率 | 53% | 40% | 100% | 100% | PASS |
| `needs_user_correction=true` | 42.22%* | 27.78%* | 100% | 100% | PASS |
| 食物名称 Top-3 | 28.89% | 22.22% | 84.44% | ≥85% | **FAIL** |
| 单一食物份量误差中位数 | 100% | 100% | 37.48% | ≤30% | **FAIL** |
| 热量区间覆盖 | 11.11% | 25.56% | 84.44% | ≥80% | PASS |
| 非食物拒答 | 100% | 100% | 100% | ≥95% | PASS |
| API p95 | 3273 ms | 12207 ms | 2945 ms | ≤8000 ms | PASS |
| 单次最高估算费用 | `$0.000077` | `$0.000086` | `$0.000068` | ≤`$0.01` | PASS |
| Provider fallback | 47 | 60 | 0 | 0 | PASS |

\* v1.0/v1.1 报告沿用了旧分母；v1.2 起按“每个有效结果都必须要求校正”计算。最终报告对
v1.2 的指标定义做了机械修正，没有追加 Provider 调用。v1.2 总估算费用 `$0.00455481`，
未确认自动写入与隐私标记均为 0。由于两项硬门禁仍失败，整体 `gate_passed=false`，
ADR-030 继续 Proposed，默认/CI/staging 继续 Mock。

## 回退矩阵

| 场景 | 用户结果 | 数据行为 |
|---|---|---|
| Feature Flag 关闭 | 隐藏/禁用图片分析入口，保留手动饮食 | 不读取图片 |
| 权限拒绝或用户取消 | 解释原因，可打开系统设置或手动记录 | 不读取/上传图片 |
| 离线 | 禁止图片分析，直接进入手动饮食 | 图片仅留在当前本地预览，离开即释放 |
| 文件过大、MIME 错误、base64 损坏 | 本地/API 明确报错，可重新选择 | 不持久化 |
| 非食物或低置信度 | `manual_required`，不展示伪精确值 | 不创建确认候选 |
| Provider 超时、限流、预算不足 | `manual_required`，不自动切到其他真实 Provider | 不重复上传，除非用户主动重试 |
| Mock | 明示演示候选，必须校正后确认 | 不外发，API 内存处理 |

## 尺度参照迭代（2026-07-29，Proposed）

为处理单张图片缺少物理尺度导致的份量误差，拍摄流程增加三种可选参照，默认仍为无参照：

| 参照 | 输入 | 拍摄要求 | 失败行为 |
|---|---|---|---|
| Journey 参照卡 | 固定 9×5 cm | 100% 打印、完整入镜、与食物同平面 | 不可见时忽略参照并保持低置信度 |
| 已知餐盘直径 | 用户输入 8—60 cm | 完整盘沿入镜、尽量俯拍 | 盘沿不完整时忽略 |
| 已知碗口直径 | 用户输入 8—60 cm | 完整碗口入镜、尽量俯拍 | 碗口不完整时忽略 |

不得使用真实银行卡、身份证或带个人信息的物品作参照。参照类型和尺寸不是健康数据，只保留
在请求与脱敏执行轨迹，不保存进饮食记录。输出新增 `scale_reference_used`，但该字段只表示
模型声称使用了可见参照，仍必须由独立评测验证，不能作为精度证明。
可打印资产：[`../assets/food-image/journey-scale-card.svg`](../assets/food-image/journey-scale-card.svg)。

独立 holdout 分两层：

1. 30 张从未进入 Prompt 调试的 Nutrition5k CC BY 4.0 无参照图片已经密封，用 source ID、
   SHA-256 和样本 ID 与 100 张调参集做零重叠校验，检测 v1.3 是否过拟合。
2. 至少 30 张带 Journey 卡/已知直径、真实称重和合法许可的配对图片。它们不得来自用户个人
   相册；未建立前，尺度改善状态明确为 `Not evaluated`。

尺度 cohort 门禁：份量相对误差中位数 ≤30%，相对同图无参照基线改善 ≥15%，参照使用判断
准确率 ≥95%，并继续满足 Schema 100%、强制校正 100%、隐私 0、自动写入 0。公开但许可
不清晰的数据集不得为了凑数量加入。

SNAPMe 官方归档约 1.89 GB，当前执行环境访问托管下载端点收到 HTTP 403；MetaFood3D 访问
需要向维护方提交申请。二者都没有在本轮下载。后续即使取得 SNAPMe，也必须把结果标为
`record-referenced`，不得在报告里称为 `weighed ground truth`；只有实际称重且共视参照的
独立数据才能关闭 ADR-030 的份量硬门禁。

`journey-food-image-scale-candidate-v0` 只保存于 Git 忽略目录，原图不进入应用包。图片中的
食物名、克重叠字和电子秤显示会直接泄露答案，因此没有把原图直接送入 Provider。同一原图
已经建立无生成式修改的 `with_ruler`/`without_ruler` 配对，遮挡叠字和秤读数；30 个电子秤
实际显示已逐格转录，全部 60 张输入已通过 contact sheet 与疑难格放大视觉检查。

用户已经再次确认取用授权，来源帖子则因关闭无法恢复。该确认足以继续 Journey 本机研发和
内部项目展示，但不能把这批素材作为开放数据集再分发，也不能宣称来源授权已由第三方独立
核验。30 组共 60 张确定性遮挡输入已固定为
`journey-food-image-scale-holdout-v1`：两版保持相同食物像素和尺寸，只在无尺版额外遮挡
尺子；清单固定 SHA-256、金标、授权边界和 `prompt_tuning_allowed=false`。

当前公开 API 仅支持 `none`、`journey_card`、`plate_diameter`、`bowl_diameter`，不能声明
图中是厘米尺；用户因此确认采用不影响正式 API 的独立版本化隔离适配器。唯一一次 Qwen
配对评测已完成，且禁止根据本 holdout 调 Prompt。

24 个完整配对的有尺份量误差中位数为 47.82%，同图无尺为 48.87%，相对改善仅 2.17%；
Schema/强制校正与参照判断均为 53/60=88.33%，fallback 7，p95 3744 ms。除延迟外主要门禁
均失败。首版报告的 4.37% 改善使用了不等数量的有效样本，已用零 Provider 调用按完整配对
修正；7 次失败用量缺失使 `$0.00144897` 只能作为费用下限。评测器已修复但不重跑密封集。

### 失败后的产品定位

当前食物图片功能只作为 Development 本机实验性辅助候选：

- 页面明确提示“模型不能通过照片准确称重”，结果点估计标注“不是称重值”；
- 用户必须打开表单修改并显式确认，图片分析本身永不写入；
- Preview、Production 和 staging 的图片开关保持关闭，正式环境不启用真实视觉 Provider；
- 厘米尺路线停止，不进入公开 API，也不使用密封集继续调参；
- 失败、离线、关闭或用户不信任结果时直接使用手动饮食记录。

保留功能是为了验证完整的隐私—候选—校正—确认链路和展示量化失败反馈，不等于声称真实
质量通过。未来重新启动需要新 ADR、新模型政策复核和新独立 holdout。

### Proposed 下一路线：识别候选与份量确认解耦

ADR-031 提出不再让视觉模型根据单张照片输出克重或热量点估计。模型只提供最多 3 个食物
名称候选和是否应拒答；用户确认名称后，在既有饮食表单中选择常用单位或输入克重，再由服务
端受控营养数据计算热量。用户已接受该产品方向；正式 App/API 没有先行修改。

下一轮独立评测集预注册为
[`../../evals/food_image_recognition_holdout/README.md`](../../evals/food_image_recognition_holdout/README.md)：
60 张全新 Wikimedia Commons 图片，覆盖中国家庭餐、单一食物、混合餐、包装食品和
非食物。每条记录保留文件页、作者和许可；全部完成隐私/视觉 QA，并与现有三套数据在来源、
source ID 和 SHA-256 上零重叠后密封。图片资产不进入仓库或应用包，密封时 Provider 调用
为 0。

总体 Top-3 门槛为 85%，中国家庭餐为 80%，非食物拒答为 95%；Schema、强制校正、禁止
自动写入和禁止模型输出克重均须 100%。2026-07-31 在重新复核 Qwen 快照、北京区域、
数据政策、价格、独立 Key 和预算后，冻结评测器完成唯一一次 60 调用：

| 指标 | 结果 | 门槛 | 状态 |
|---|---:|---:|---|
| 总体食物名称 Top-3 | 37/55 = 67.27% | ≥85% | **FAIL** |
| 中国家庭餐 Top-3 | 12/20 = 60% | ≥80% | **FAIL** |
| 非食物拒答 | 5/5 = 100% | ≥95% | PASS |
| Schema / 强制校正 / 禁止估重 | 59/60 = 98.33% | 100% | **FAIL** |
| 评测降级/失败 / p95 | 1（无后备模型调用）/ 3416 ms | 0 / ≤8000 ms | **FAIL / PASS** |
| Token/费用记录 | 60/60 | 100% | PASS |
| 总估算费用 | $0.00240432（约 ¥0.0173） | ≤$0.02 且 ≤¥1/日 | PASS |
| 未确认自动写入 | 0 | 0 | PASS |

结果不得反向用于调整当前 Prompt 或金标。冻结别名评分对部分合理同义词过严是已知评测
局限，但不能作为事后改分依据；ADR-031 保持 Proposed，正式产品不启用该真实模型路线。

### v1.3 密封无参照 holdout 结果

`journey-food-image-holdout-v1` 包含 15 张单一食物和 15 张混合餐，与调参集三重零重叠。
它不含尺度参照，所以只回答“v1.3 在未见图片上是否保持泛化”，不回答“参照是否改善份量”。

| 指标 | 结果 | 门槛 | 状态 |
|---|---:|---:|---|
