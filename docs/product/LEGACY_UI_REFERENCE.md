## 3. 页面结构与关键文案

### 首页

源码：`src/pages/home/main.jsx`

结构：

1. Mint 渐变 Hero：日期、目标、日常消耗、问候、今日热量结余、饮食/活动条数。
2. 记录入口：饮食与活动两张卡通图片卡片。
3. 今日概况：净结余、活动消耗、已摄入、日常消耗。
4. 今日更新：按时间展示饮食与活动，3 条一页。
5. 今日贴纸：AI 建议或本地柔化文案，使用日常叶子角色。

值得保留的语义：

- “随手记下一条，今天的变化就会跟着更新。”
- “热量结余 = 已摄入 - 活动消耗 - 日常消耗。”
- 今日数据、近期记录和轻量建议同屏。

需要重做：统一 Agent 输入、意图拆分、候选确认、工具状态、引用和离线提示。

### Journey / 里程

源码：`src/pages/journey/main.jsx`

结构：

1. Hero：最近状态、累计饮食/活动和体重变化估算。
2. 日期选择。
3. 5 天一页的多日卡片。
4. 每日状态、热量结余、饮食列表、活动列表。
5. 前后页和继续加载。

值得保留的语义：时间线、多日回看、趋势与当日记录归档。新产品统一使用 “Journey” 名称，不保留“里程”作为技术命名。

### 我的

源码：`src/pages/profile/main.jsx`

结构：

1. 用户昵称与当前目标。
2. 性别、身高、体重、体脂率。
3. 日常消耗估算与方法说明。
4. 昨日热量差对应的理论体重变化。
5. 资料编辑、保存和错误状态。

值得保留的语义：画像、目标、单位、身体指标和计算依据可见。新项目需要加入账号、安全、隐私、离线知识和数据删除入口。

### 饮食记录

源码：`src/pages/food/main.jsx`

结构：AI 自然语言估算 → 候选列表 → 用户确认写入；并保留餐别、名称、热量的精确表单和今日记录编辑/删除。

值得保留：模型结果必须先预览再写入、手动表单作为降级路径、写入后同步首页/Journey。

### 运动记录

源码：`src/pages/activity/main.jsx`

结构与饮食相同：自然语言估算 → 候选确认；并保留名称、热量的精确表单和记录管理。

需要改进：新 schema 应增加时长、强度、距离等结构化字段，不能只保存名称和 kcal。

### 登录与邀请码

源码：`src/pages/auth/index.jsx`、`src/pages/invite/index.jsx`

这两个页面完全服务微信登录和邀请码激活，不迁移 UI 或流程。新项目使用邮箱/用户名密码和环境受控测试账号。

当前真实状态：登录页能够渲染和调用按钮，但请求的旧后端地址
`http://127.0.0.1:8000` 不可达，无法取得业务会话，也无法自然进入邀请码或首页。
本阶段不修复该旧流程；其失败截图作为退役依据保留。

## 4. 设计风格清单

### 色彩

- 主色：mint，核心值 `#74c7a2`、`#4fb387`、`#2f8f68`。
- 页面背景：从 `#ecfbf3` 到 `#fbfffd` 的浅绿渐变。
- 主文字：`#214135`，次级文字：`#4d6a5f`。
- 饮食/摄入：salmon/rose，核心值约 `#ec7f61`。
- 运动/消耗：mint 深色，核心值 `#2f8f68`。
- 危险操作：`#d96b6b`。

### 形状和层级

- 大圆角卡片：旧值 28–44 rpx；React Native 中需转换为独立 dp token，不能机械除以二后即定稿。
- 轻边框：`#d7ebe1`。
- 低对比绿色阴影，避免强烈浮层感。
- Hero 使用 mint 渐变和浅色装饰圆。
- 卡片间距大于表单内部间距，整体留白偏松。

### 字体

- 旧端字体栈：PingFang SC、Hiragino Sans GB、Microsoft YaHei。
- 字号层级：display 68 rpx、title 38 rpx、subtitle 30 rpx、body 28 rpx、small 24 rpx、caption 22 rpx。
- 新端需按 iOS/Android 动态字体和无障碍重新定义，不照搬 rpx。

### 动效

- 旧 token：fast 160 ms、base 220 ms。
- 新端只保留轻量状态反馈；Agent 流式和工具进度另建明确状态，不用无意义动画遮挡延迟。
