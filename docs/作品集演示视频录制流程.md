# Journey 作品集演示视频录制流程

这份流程用于录制一条 2 分 30 秒至 3 分钟的作品集视频，同时产出 README 需要的界面截图。视频重点不是逐页介绍功能，而是讲清楚 Journey 如何把一段自然语言安全地转成可确认的健康记录，再生成有依据的周总结。

## 录制前准备

1. 使用 `main` 分支，按 README 完成安装和启动。
2. 保持默认 Mock Agent，不填写任何外部模型密钥。
3. 在登录页创建一个全新的本地账号，使用虚构的昵称、邮箱和记录数据。
4. 预先设置身高、目标体重和每日能量目标，避免录制时长时间填写表单。
5. 关闭桌面通知、聊天软件和密码管理器弹窗，清理浏览器书签栏与无关标签页。
6. 固定画面尺寸。推荐 Web 使用 1440 × 900；录制手机画面时统一使用同一台 iPhone Simulator 和同一套明暗主题。
7. 不录制密码输入过程，也不要展示真实邮箱、访问令牌、API 密钥、内部调试 ID 或个人健康数据。

建议先完整彩排一次，再正式录制。操作失败时直接重录该段，后期剪掉等待、输入和页面加载过程。

## 视频分镜

### 1. 开场与定位（0:00–0:12）

画面展示 Journey 标志与首页，旁白可以说：

> Journey 是一个面向个人的健康生活记录应用。它把饮食、运动和体重记录放在一个时间线里，并用可确认的 Agent 流程生成建议和周总结。

不要在开场展示代码、终端或架构图，先让观众看到成品。

### 2. 自行注册与进入首页（0:12–0:28）

快速展示“创建账号”入口，剪掉密码填写过程，直接切到注册完成后的首页。强调账号与数据默认保存在本地环境。

**在首页干净、无弹窗时截图 1：** 保存为 `docs/assets/readme/01-home.png`。这张图用于 README，负责建立第一印象。

### 3. 画像与目标（0:28–0:45）

展示个人画像和目标设置结果，例如身高、目标体重与每日能量目标。这里只展示最终状态，不逐项输入。

旁白说明：后续建议会结合用户主动提供的目标，但 Journey 不做医疗诊断。

### 4. Multi-Agent 核心闭环（0:45–1:25）

回到首页，在统一输入框输入：

```text
今天中午吃了一份牛肉面，晚上跑了5公里，我这周减脂情况怎么样？
```

点击“理解并处理”，依次展示执行计划、饮食候选、运动候选和周总结。重点说明两件事：

- 一段话会被拆成不同任务处理；
- Agent 只生成候选，真正写入前必须由用户确认。

**在执行计划和候选卡片完整出现、尚未确认写入时截图 2：** 保存为 `docs/assets/readme/02-agent-result.png`。这张图最能体现项目的 AI 差异化。

随后打开两个候选，快速核对并确认写入。录屏中保留一次“确认”动作即可，第二次可加速或剪切。

### 5. 记录落地（1:25–1:43）

展示首页统计或 Journey 时间线已经出现牛肉面与 5 公里跑步记录，证明 Agent 结果最终落到了真实业务数据，而不是一次性聊天文本。

这一段不必单独放进 README；如果首页记录后的状态比截图 1 更完整，可以用它替换 `01-home.png`。

### 6. 有依据的周总结（1:43–2:08）

进入 Journey 页面，生成近 7 天总结，展示记录覆盖、结论和“依据”信息。旁白说明总结可以追溯到已确认的记录，而不是无来源生成。

**在周总结、时间线和依据同时清晰可见时截图 3：** 保存为 `docs/assets/readme/03-journey-summary.png`。这张图用于完成“输入—确认—总结”的故事闭环。

### 7. 隐私与受控 AI（2:08–2:30）

进入隐私或相关设置，展示默认 Mock 模式、外部 AI 开关和数据控制能力。避免展开内部供应商审核、密钥轮换等尚不适合普通观众的运维细节。

可以额外保存 `docs/assets/readme/04-privacy.png`，但 README 首版建议只放前 3 张，保持简洁。

### 8. 工程能力与收尾（2:30–2:50）

最后用 10 至 20 秒展示 GitHub 仓库首页和绿色 CI，简短带过 Expo、FastAPI、PostgreSQL、自动化测试与隐私保护。不要滚动大段代码。

收尾旁白可以说：

> Journey 展示的不只是模型调用，而是一条能解释、可确认、可测试，也尊重数据边界的 AI 产品链路。

## README 截图放置方式

正式截图完成后，创建 `docs/assets/readme/`，放入以下 3 张经过裁切的 PNG：

```text
docs/assets/readme/01-home.png
docs/assets/readme/02-agent-result.png
docs/assets/readme/03-journey-summary.png
```

三张图应使用相同尺寸、主题和圆角，不包含鼠标指针、通知、真实账号信息或空白加载状态。图片建议先压缩，单张尽量控制在 500 KB 以内。

然后在 README 的项目简介与“快速开始”之间加入：

```html
## 界面预览

<p align="center">
  <img src="docs/assets/readme/01-home.png" width="30%" alt="Journey 首页" />
  <img src="docs/assets/readme/02-agent-result.png" width="30%" alt="Agent 执行计划与确认候选" />
  <img src="docs/assets/readme/03-journey-summary.png" width="30%" alt="Journey 周总结与依据" />
</p>
```

在图片尚未拍好并提交之前，不要提前加入这段 HTML，否则 GitHub README 会出现破图。

## 发布前检查

- 视频中没有出现密码、密钥、真实邮箱、真实健康信息或系统通知。
- 三张 README 截图能独立讲清首页、AI 确认门和周总结。
- 视频使用的是 Mock Agent；没有把模拟结果描述成医疗建议或真实模型能力。
- GitHub 仓库的 README 上手步骤可以从全新环境完成，并明确要求用户自行创建账号。
- 结尾展示的 CI 对应当前 `main` 分支且状态为绿色。
